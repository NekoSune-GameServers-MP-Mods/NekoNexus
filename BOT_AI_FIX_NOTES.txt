SHIPPED - 4.7.12 (the actual "floating" root cause)
===========================================================
Root cause found: the client's AvatarAnimationController (Core/UberStrike.
Game/AvatarAnimationController.cs) drives the walk/run/idle/grounded
animator blend tree ENTIRELY from the position update's Velocity and
KeyState/MovementState bytes (WalkingSpeed <- Velocity magnitude,
IsWalking <- KeyState, IsGrounded <- MovementState & Grounded). BotBrain
was only ever writing Position + HorizontalRotation each tick - Velocity/
KeyState/MovementState stayed at their zero defaults forever. Result:
position genuinely moved every tick (confirmed correct in 4.7.11), but
every other client rendered the bot playing a static idle pose while
sliding across the ground/air - exactly the "floating, not walking like
a normal human" look, independent of the 4.7.11 vertical-speed fix.

Fix (BotBrain.Tick / MoveToward):
  - Tick() now resets Velocity=zero, KeyState=Still, MovementState=
    Grounded every tick before Engage/Patrol run (mirrors a real client
    reporting "standing still, grounded" by default).
  - MoveToward() overwrites Velocity (direction * TICK_TRATE, i.e. actual
    per-second speed) and KeyState=Forward whenever it actually moves the
    bot that tick.
  - actor.UpdatePosition = true is now set unconditionally each tick
    (matches how a real client's UpdatePositionAndRotation op always
    marks it dirty), so a bot stopping is promptly broadcast instead of
    other clients keeping a stale "walking" animation state.
Build verified clean (0 errors) after this change.

===========================================================
1. TDM MATCH TIMER STUCK AT 05:00 (not counting down)
2. TDM BOTS DON'T GO AFTER ENEMIES

Extensive static investigation was done for both (traced the full
client-server match-countdown time-sync chain: PhotonPeer TimeSync op
254 <-> RealtimeHost, GameState.StartMatch/GameTime/RemainingTime,
GameStateHelper.UpdateMatchTime called every frame from the client's
MatchRunningState.OnUpdate - the sync mechanism itself looks intact and
was already fixed once before per memory nekonexus-live-economy-
stability.md "MATCH COUNTDOWN FIX (was stuck at 10:00)" from 2026-06-26).
Also traced the TDM team-balance path end to end (PickBotTeam alternates
correctly as bots are added; TeamDeathMatchRoom.CanStartMatch requires
>=1 BLUE and >=1 RED; PreparePlayer does NOT touch Team so it can't be
getting reset between rounds; AcquireTarget's same-team skip logic reads
correctly). Every concrete hypothesis I could form and check via static
reading was ruled out - couldn't reproduce or pin an exact root cause
without seeing this actually happen live.

Added targeted diagnostic logging instead, so the NEXT time this
reproduces, the server log will show the answer directly instead of more
guessing:
  - MatchRunningState.cs OnPlayerLeft: logs blue/red/total player counts
    whenever a mid-match leave (bot or human) drops CanStartMatch to
    false and force-ends the round early.
  - PrepareNextRoundState.cs OnPlayerLeft: same logging when a leave
    during the pre-match countdown stops it (this would explain a match
    that never actually reaches MatchRunning - frozen bots + frozen
    "05:00" placeholder timer would look exactly like what was reported).
  - BaseGameRoom.Bots.cs AddBot(): now logs each bot's assigned team, so
    a lopsided team split (e.g. all bots ending up on one side) would be
    visible immediately in the log.

NEXT STEP: reproduce a TDM match with bots again, then grab the Realtime
server log covering that session (bot adds with their team, and any
"dropped CanStartMatch to false" lines) and share it. That will very

SHIPPED - 4.7.13 (admin-controlled toggle, BETA, off by default)
===========================================================
User asked for an enable/disable option, off by default, labeled BETA,
AND an actual UI ("bot enabled menu... like in UI or something") rather
than just a config file edit. Implemented the same way the existing
global 2x/5x coin-boost admin feature works (BoostManager/BoostState
pattern) instead of a YAML setting, so it can be flipped with no
realtime restart:

- New DB table `BotsConfig` (Id=1, Enabled/FillTarget/MaxBots), owned by
  the admin service, created lazily on first use. Seeded Enabled=0.
- Admin API: GET/POST /api/config/bots (packages/admin/src/index.ts) -
  same shape as /api/config/boost. POST persists then best-effort calls
  the ws internal bridge so it applies live.
- ws: new `/internal/set-bots-config` bridge endpoint (WebServiceHost.ts,
  INTERNAL_API_KEY-gated) + new `BotsConfigManager.ts` (mirrors
  BoostManager.ts) caching the current value in memory, broadcasting to
  all connected Game servers on change, and re-pushing to a Game server
  the moment it (re)connects (wired into NekoNexusService.ts alongside
  BoostManager's same two hooks).
- New master-socket packet `SetBotsConfig` added to BOTH enums in
  lockstep (packages/Realtime/.../WebSocket/WebSocket.PacketType.cs and
  packages/ws/src/ServiceHosts/WebSocket/PacketType.ts), wired into both
  Payload (de)serializers (C# decode-only; TS encode+decode) - it's a
  plain { Enabled, FillTarget, MaxBots } dict, same wire shape as
  SetBoost.
- New `BotsConfigState.cs` + `GameServerApplication.BotsConfig` (static,
  volatile, mirrors `Boost`) - updated from the SetBotsConfig case in
  GameServerApplication's master-socket DataReceived switch.
- `BaseGameRoom.Bots.cs` ComputeTargetBotCount now reads
  `GameServerApplication.BotsConfig` instead of
  `Configuration.GameplaySettings` - the YAML BotsEnabled/BotFillTarget/
  MaxBots fields are REMOVED from ApplicationConfiguration.cs and both
  shipped config templates (packages/Realtime/NekoNexus.Realtime/
  NekoNexus.Realtime.yml, docker/config/NekoNexus.Realtime.yml) since
  they're superseded by the DB-backed admin setting.
- Admin dashboard UI: new "AI fill bots" card on the Gifts & Events page
  (packages/admin/src/dashboard.html) with a Beta badge, Enabled select,
  FillTarget/MaxBots number inputs, and a save button - mirrors the
  existing Global coin boost card's layout/JS pattern exactly
  (loadBots()/save handler alongside loadBoost()).
- Verified: NekoNexus.Realtime rebuilds clean (0 errors). ws and admin
  packages both bundle clean with `bun build --target=bun` (bun doesn't
  type-check, but this catches syntax/unresolved-import errors); ran
  `tsc --noEmit` against packages/ws too - filtered for the specific
  files touched here and found zero errors from this change (the
  tsc run surfaces a large pile of PRE-EXISTING path-alias errors across
  nekonexus-models/uberstrike-js unrelated to this feature - do not treat
  those as caused by this work).
- NOT tested live (no way to run the actual admin dashboard + a
  connected Game server + browser in this environment) - next step is
  for the user to redeploy admin+ws+realtime and click the toggle on a
  live server to confirm the end-to-end push actually works.
